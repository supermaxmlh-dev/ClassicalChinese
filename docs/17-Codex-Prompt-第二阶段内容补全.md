## 二、必须满足的硬条件（校验会拦，照此写才能一次过）

1. **原文一致**：`## 原文`（去 ruby）必须与 `content/raw` 底本逐字相同（`assertSameOriginal`）。用权威《古文观止》通行本，逐字校对不得臆造漏字。
2. **朗读节奏对齐**：`## 朗读指导` 去 "/" 后须与原文逐字相同且完整覆盖。
3. **填空题多答案格式**（新）：`## 参考答案` 第 4 题用 `字：答案1/答案2`（半角 `/` 分隔同义答案，第一个为标准答案），如 `谏：规劝/劝谏；克：战胜/攻克`。加点字在题干用 `**加粗**` 标出，且句子须是原文片段；**严禁"略"或空答案**。
4. **frontmatter 与 `data/curriculum.json` 完全一致**（id/title/week/difficulty）。
5. 每篇：逐句精读非空、全文翻译非空、keyVocab ≥5 行。

## 三、质量基线（吸取第一阶段教训，务必避免以下问题）

- **选择题不许水题**：❌ 禁止"本文题目是下列哪一项？"这类无效题。每道选择题都要考**字词理解 / 古今异义 / 文意把握 / 名句**，每篇 2–3 道；解析 ≥10 个汉字、讲清为什么对与易错项错在哪，**不得**用"符合原文语境/其他选项不符合本句含义"等套话（黑名单会报错）。
- **逐句精读要分段**：按自然段/意义段拆成**多段**（250 字以上的至少 3 段，切忌整篇塞成一段）。700–750 字长篇（055 郑伯克段于鄢、062 冯谖客孟尝君）建议分 2 课时式的更多小段，逐段注释+翻译。
- **拼音随文取义**（重点，沿用 `docs/13`/`14` 规则）：原文注音由 pinyin-pro 自动生成，需在 raw 用手工 `<ruby>` 覆盖文言特殊读音——**破读**（食sì/王wàng/衣yì/语yù/数shuò…）、**通假**（说→悦yuè、见→现xiàn、知→智zhì、女→汝rǔ、邪→耶yé…）、**专名异读**（召shào、知氏zhì…）、**文言虚词**（夫fú、与/邪 语气 yú/yé）、以及**朝=早晨读 zhāo**（与夕/暮对举时）。拿不准的**不要猜**，登记到 `docs/pinyin-校正报告.md` 存疑区。
- **受众为中小学生**：语言清晰、由浅入深；★★ 篇可稍详，★★★ 篇按"重点句注释"。思考题开放、至少 1 题联系学生生活。
- **风格一致**：与已完成的 001–050 篇保持同样体例、语气、注释密度（可对照 `content/samples/week03-013-烛之武退秦师.md`、`week09-036-*` 等）。

## 六、工作流程（按周分批，逐批验收）

1. **每次只做一周**（先第 14 周 051–054），建该周 raw + sample。
2. 跑 `npm run build` **全绿**再继续；报错按提示修。
3. 该周过后 `git commit`（如 `feat: add week 14 articles 051-054`），再下一周。
4. 15 周（14–25，含 15/23/24 为 3 篇）文章全部完成后，做第 26 周期中测评扩充，再 build 全绿、commit。
5. 收尾确认 `data/content-status.json` 中第 14–25 周文章 `status` 均为 `complete`。

**每完成一周请输出**：新增文件、`npm run build` 结果、本周自查（原文一致 / 填空无"略"且用多答案格式 / 选择题无水题无套话 / 精读已分段 / 拼音特殊读音已覆盖并记录）。等我确认再继续下一周。
