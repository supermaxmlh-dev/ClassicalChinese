## 二、每篇要产出的两个文件

1. **原文底本** `content/raw/{id}-{篇名}.txt`
   - 只放原文，可在生僻/易错字上加 `<ruby>字<rp>(</rp><rt>pīn</rt><rp>)</rp></ruby>`。
   - 自然分段用空行。**全篇用权威《古文观止》通行本原文，逐字校对，不得臆造或漏字**。
2. **教学稿** `content/samples/week{NN}-{id}-{篇名}.md`（NN=两位周次，如 `week06-023-齐桓下拜受胙.md`）
   - 严格按 `docs/05-文章内容模板.md` 的 10 个模块。

## 三、教学稿模块与「解析器硬要求」（照此写才能一次过校验）

按顺序包含以下标题（解析器靠这些 `##` 标题切块，缺一不可）：

```
# {篇名}

---
id: {三位数}
title: "{篇名}"
source: "{出处}"
author: "{作者}"
dynasty: "{朝代}"
difficulty: {1-5}
week: {周次}
word_count: {约字数}
tags: ["...", "..."]
related_idioms: ["..."]
---

## 故事导读
（80–150字，口语化讲故事，留悬念）

## 原文
（与 raw 底本逐字一致，含相同 <ruby> 标注）

## 朗读指导
（用 "/" 标停顿；除 "/" 外的文字必须与原文逐字一致、完整覆盖全文）

## 逐句精读
### 第一段
> {该段原文}
**注释**：
- **{词}**：{解释}
**翻译**：{白话}
**古今联系**：{1-2点，可选}
（按自然段重复若干段）

## 全文翻译
（通顺完整白话译文）

## 延伸阅读
### 关于作者
### 历史背景
### 你知道吗？
### 相关故事

## 想一想
1. …（2-3题，至少1题联系学生生活）

## 小试牛刀
### 一、选择题
1. {题干}
   - A. …
   - B. …
   - C. …
   - D. …
（2-3题）
### 二、填空题
4. 写出下列加点字的意思：
   - {句中把考点字用 **加粗** 标出，如}晋**军**函陵 → ______
   - 何**厌**之有 → ______
（加点字即考点；每个加点字的句子必须是原文中的片段）
### 三、简答题
5. {题}
### 四、挑战题（选做）
6. {题}

## 词汇积累

|----|------|------|------|----------|
| … | … | … | … | … |
（至少 5 个词，整篇 keyVocab 不得为空）

## 参考答案
1. {正确项字母}（{选项文字}）。{为什么对、易错项错在哪——具体讲解，≥10个汉字，禁止套话}
2. …
3. …
4. {加点字}：{答案}；{加点字}：{答案}；{加点字}：{答案}
5. {简答参考}
6. {挑战参考}
```

**会被校验脚本拦截、必须满足的硬条件：**

1. **原文一致**：`## 原文`（去掉 ruby 后）必须与 `content/raw` 底本逐字相同，否则构建报 `Original text mismatch`。
2. **朗读节奏对齐**：`## 朗读指导` 去掉 "/" 后必须与原文逐字相同且完整覆盖，否则报 `Rhythm text mismatch / does not cover`。
3. **拼音标注**：`<ruby>` 的拼音要正确（多音字按文中读音，如"说→yuè、知罃→yīng"），位置由脚本自动计算。
4. **填空题不留空**：每个加点字都要在「## 参考答案」第 4 题里给出 `字：答案` 映射；**严禁出现 "略" 或空答案**（会构建失败）。加点字句子必须能在原文中找到。
5. **选择题解析要有料**：每题解析 ≥10 个汉字，且**不得包含**「符合原文语境」「其他选项不符合本句含义」这类模板套话（已被列入黑名单，命中即报错）。
6. **frontmatter 必须与 `data/curriculum.json` 对应条目完全一致**（id、title、week、difficulty）；word_count 用上表约数即可。
7. 每篇至少 1 道选择题、逐句精读非空、全文翻译非空、keyVocab 至少 1 行。

## 六、工作流程（按周分批，逐批验收）

1. **每次只做一周**（如先做第 6 周 023–026），创建该周 4 篇的 raw + sample。
2. 运行 `npm run build`（= build:data + validate-data + validate-curriculum），**直到全绿**再继续；报错按提示修对应文件。
3. 该周通过后 `git commit`（如 `feat: add week 6 articles 023-026`），再进入下一周。
4. 七周文章全部完成后，做第 13 周测评扩充，再 `npm run build` 全绿、commit。
5. 全部完成后，确认 `data/content-status.json` 中第 1–12 周文章 `status` 均为 `complete`、第一阶段无 `missing`。

**每完成一周请输出**：新增了哪些文件、`npm run build` 结果、本周篇目自查（原文一致/填空无"略"/解析无套话）。等我确认再继续下一周。
