# A · 管理后台「请求过于频繁」修复

## 问题

打开站长后台审核几条就报「请求过于频繁」。根因在 `api/shared/feedback.js`：

```
verifyAdminRequest() {
  if (adminTooManyRequests(ipHash)) → 429   // ← 先计数，且不论成功失败都计
  if (!verifyAdminToken(...)) → 401
}
```

`adminTooManyRequests()` **对每一次管理请求都累加计数**（含验证通过的正常操作），而 `ADMIN_RATE_LIMIT_MAX = 10` / 10 分钟。而后台每个动作不止一次请求：登录拉队列 1 次；每点「通过/退回/删除」= 操作 1 次 + `loadQueue` 刷新 1 次 = **2 次**；手动刷新 1 次。于是**审 4~5 条就把配额用完**，站长被自己的限流挡住。

## 修法（保留防爆破，但不拦已验证的站长）

1. **只对「验证失败」计数**：把限流计数移到**口令校验失败之后**——口令正确的请求**不计入**失败桶（或校验成功时清零该 IP 的失败计数）。失败累计超过阈值（建议 10 次/10 分钟）才返回 429。
2. **给已验证的管理操作一个宽松上限**（防脚本失控即可），如 300 次/10 分钟，正常审核绝不会触发。
3. **区分 429 文案**，便于排查：
   - 口令错误过多 → 「口令错误次数过多，请稍后再试」
   - 普通用户提交过快 → 保持「提交过于频繁，请十分钟后再试」
4. **减少冗余请求**（`js/admin.js`）：`PATCH`/`DELETE` 成功后，**就地更新该条目的状态**或从列表中移除，不要每次都整表 `loadQueue`；保留手动「刷新」按钮即可。
5. **限流阈值改为环境变量可配（带默认值）**：现在四个参数都写死在代码里，调一次要改代码重部署。改为从 `process.env` 读取、解析失败或未设置时回落到默认值：
   - `ADMIN_RATE_LIMIT_MAX`（默认 **10**）——管理口令**失败**尝试上限
   - `ADMIN_RATE_LIMIT_WINDOW_MS`（默认 **600000**，即 10 分钟）
   - `FEEDBACK_RATE_LIMIT_MAX`（默认 **5**）——普通用户提交上限
   - `FEEDBACK_RATE_LIMIT_WINDOW_MS`（默认 **600000**）
   - 另加 `ADMIN_OPS_RATE_LIMIT_MAX`（默认 **300**）——已验证管理操作的宽松上限（见第 2 条）
   要求：用 `Number(process.env.X)` 解析，**非正数/NaN 一律用默认值**；把这些变量补进部署说明（README 或 `docs/22` 的 Phase 2 小节），注明含义与默认值。

## A 验收

- 用**正确口令**连续审核 20 条以上，**不再出现 429**。
- 用**错误口令**连续尝试：第 11 次左右返回 429，且文案为「口令错误次数过多…」；等窗口过后可再试。
- 普通用户提交反馈的限流（默认 5 次/10 分钟）行为不变。
- **环境变量可配生效**：不设任何变量时按默认值（管理失败 10 次、用户提交 5 次、窗口 10 分钟）；把 `ADMIN_RATE_LIMIT_MAX` 设为 3 后，错口令第 4 次即触发 429；设为非法值（如 `abc`、`0`、`-1`）时自动回落默认值、不崩。
- `npm run build` 前端仍全绿。

# B · 字典/注释「模糊释义」精确化

## 问题

字典里 `之`「代词或助词，需结合上下文理解」、`其`「代词或语气词，需结合上下文理解」——这等于没解释，对学生无用。

**根源在源内容**（字典只是聚合）：`content/samples/*.md` 的逐句精读注释里共 **67 处**、分布在 **18 个文件**，形如：

```
- **之**：代词或助词，需结合上下文理解
- **其**：代词或语气词，需结合上下文理解
```

## 修法

**逐处按该句实际用法改写为具体释义**（在 `content/samples/*.md` 里改；`data/` 为生成物，改完重建）。参考义项（按上下文选一，**不要照抄全部**）：

- **之**：① 的（山川**之**美）；② 他/她/它/他们（肉食者谋**之**）；③ 到、往（辍耕**之**垄上）；④ 用于主谓之间取消句子独立性、不译（齐国**之**美丽者也）；⑤ 宾语前置的标志、不译（何陋**之**有）。
- **其**：① 他的/它的/他们的（以**其**无礼于晋）；② 那、那个（**其**岸势犬牙差互）；③ 难道（**其**真无马邪）；④ 恐怕、大概（**其**皆出于此乎）；⑤ 表祈使、还是（吾**其**还也）。

**要求**：
- 每处都要写**该句中的确切用法**，可采用「用法 + 直译」的写法，如：`- **之**：代词，指"这件事"（谋之＝谋划这件事）`、`- **其**：代词，他的（指晋国的）`。
- **不得**再出现"需结合上下文""视语境而定"等空泛说法；也**不要臆造**——拿不准的按通行教材注释，仍不确定则在报告中列出待人工定夺，不要硬写。
- 面向中小学生，措辞浅白。

## 加固（防复发）

在 `scripts/validate-dictionary.js`（及/或 `validate-data.js` 对 `sections[].annotations`）增加校验：义项/注释的释义中**命中"需结合上下文/结合上下文理解/视上下文/根据语境"等空泛表述即报错**，构建失败。

## B 验收

- `grep -rn '需结合上下文' content/ data/` **无输出**。
- `npm run build`（build:data + build:dictionary + validate-*）**全绿**，且新增的空泛表述校验能在故意写回一条时报错。
- 打开 `pages/dict.html` 查「之」「其」：每个义项都是具体解释（如"的""他/它""取消句子独立性"等），无"需结合上下文"字样。
- 抽查 001 曹刿论战、021 郑庄公戒饬守臣、037 项羽本纪赞 的逐句精读注释，`之`/`其` 均为该句确切用法。
