# 观止学堂 · 功能扩展执行计划（Roadmap + Codex 驱动 prompt）

> 目标：分阶段落地 6 项新功能。**逐阶段执行、每阶段独立可上线**；每阶段 `npm run build` 全绿并 `git commit` 后再进下一阶段。本文件既是路线图，也是给 Codex 的分步 prompt——按 Phase 顺序把对应小节交给 Codex。

## 首要原则 · 本地优先（local-first，不可违背）

**学习功能永远只依赖静态资源 + cookie，不得依赖后端；账户与所有在线功能一律是"可降级的叠加层"，网络或登录不可用时自动隐藏/禁用，绝不阻断学习。**

- **本地即完整**（无网、无账号都能用）：阅读全部文章、拼音/节奏、逐句精读、翻译、字典查阅、选择/填空判分、学习进度、称号——全部跑在静态内容 + cookie + 本地 JS 上。**cookie 始终是本设备学习进度的唯一即时真源。**
- **在线只是加成**（有网 + 登录才出现）：AI 打分、留言反馈、跨设备同步、排行榜——做成优雅降级；检测不到网络/未登录就灰掉或提示"联网后可用"，页面其余部分照常。
- **登录不夺主权**：登录只是把 cookie 进度**合并上云做备份/同步**，本地 cookie 仍是即时真源；登录后断网仍用本地 cookie 学，联网后再同步。
- **每次调 `/api` 必须有失败兜底**：超时/离线/未登录一律回退本地模式，不得抛错阻断页面。
- 涉及后端的 Phase（2/3/5）**验收都必须包含**："断网 + 未登录时，阅读/判分/进度/字典完全正常，只是在线功能隐藏或提示不可用"。

## 关键背景（决定顺序的架构拐点）

当前是**纯静态站点**（HTML/CSS/原生 JS + 预生成 JSON + cookie 存进度），Azure Static Web Apps（下称 SWA）部署，**无后端**。
- 第 1、4 项可在**静态前端内**完成（低风险，先做）。
- 第 2、3、5 项**必须引入后端**（不能把 API 密钥放前端）。推荐用 **SWA 内置的 Azure Functions（`/api` 目录）** + **SWA 内置认证**，与现有部署无缝衔接，无需自建服务器。
- 第 6 项是**协作/流程**为主，技术上依附第 3、5 项。

**先决策（请在动手前确认，直接影响实现）：**
- **AI 提供方与密钥**（第 2 项）：用哪家大模型 API？密钥只能放后端 Functions 的环境变量，不得进前端。
- **后端平台**：默认 **Azure Functions（`/api`）**；如不想上后端，第 2/3/5 项需改用第三方（如表单服务、Auth0、外部数据库），成本与耦合不同。
- **未成年人隐私（重要）**：本站面向中小学生。账户、AI 反馈、邮箱/留言都涉及未成年人数据——**最小化收集 PII、需家长/监护同意、数据可删除**，并遵守适用法规（如中国《个人信息保护法》及未成年人相关规定）。每个涉及数据的阶段都要落实这条。

## 执行顺序（按依赖与风险排序）

Phase 0（进行中）拼音复校 → 1 古文字典（静态，高杠杆）→ 2 反馈入口（首个后端）→ 3 AI 评估打分（复用后端+字典）→ 4 账户与排名（认证+数据库，最重）→ 5 教师协作校验（依附账户）。

## Phase 1 · 挂载古文字典（第 4 项）— 静态优先，高杠杆

**为什么先做**：纯前端即可实现；同时支撑第 2 项（喂给 AI 判断）和 Phase 0（校拼音/释义）。

- 数据：新增 `data/dictionary.json`，字段建议 `{ char, pinyin[], radical, senses:[{def, example}], variants[] }`；先覆盖已出现篇目的高频文言字（可从各篇 `keyVocab`/`annotations` 汇总起步，再逐步扩充）。用 `scripts/build-dictionary.js` 从现有内容聚合生成，纳入 `npm run build`，并加 `validate` 校验（无空义项、拼音合法）。
- 前端：`pages/dict.html` + `js/dict.js`，支持按字/拼音/词义检索；文章页点注释词时可跳转/浮层查字典。
- 复用于校验：字典即"权威读音/释义"参照，Phase 0 与 Phase 3 都引用它。
- **验收**：能检索到字与义项；`npm run build` 全绿；文章注释词可查字典。

---

## Phase 2 · 反馈入口：留言板 + 邮件（第 3 项）— 首个后端

**为什么此时**：这是**最小的后端**，用来把 SWA 的 `/api` + Functions 基础设施立起来，风险可控。

- 后端：新建 `/api/feedback`（Azure Function，HTTP POST）。两种落地二选一或都做：
  1. **邮件**：Function 调邮件服务（如 Azure Communication Services / SMTP）把反馈发到你邮箱；
  2. **留言板**：Function 把反馈写入轻量存储（Azure Table/Cosmos DB free tier），`GET /api/feedback` 读取展示。
- 前端：`pages/feedback.html` 反馈表单（页面/篇目、问题类型、内容、可选联系方式）；提交调 `/api/feedback`。
- 防滥用与隐私：加简单校验/限流/敏感词；联系方式可选、明示用途、可不填；未成年人不强制留真实身份。
- 配置：`staticwebapp.config.json` 增加 `/api/*` 路由；密钥/连接串放 Function 环境变量。
- **验收**：本地/预览环境提交反馈成功；邮件到达或留言入库并可查看；`npm run build` 前端仍全绿；**断网/未登录时反馈入口优雅禁用或提示，阅读/判分/进度/字典完全正常**。

## Phase 3 · AI 阅读评估与打分（第 2 项）— 复用后端 + 字典

**依赖 Phase 2 的后端、Phase 1 的字典。**

- 后端：`/api/evaluate`（Function）代理大模型：接收 `{articleId, questionType, studentAnswer}`，服务端拼 prompt（含该篇原文/参考答案/字典释义作依据），调 LLM，返回 `{score, rubric[], feedback, corrections[]}`。**密钥仅在后端**。
- 用途：给**简答题/翻译/仿写**这类开放题打分与反馈（选择/填空仍走现有本地判分）。
- 前端：文章页开放题加"提交给 AI 评估"，展示分数+逐条反馈+修改建议。
- 护栏（面向未成年人，重要）：反馈语气鼓励、就事论事；**只评语文作答，不采集与学习无关的个人信息**；对不当输入安全兜底；标注"AI 反馈仅供参考"。限流与调用成本控制。
- **验收**：对样例作答返回结构化评分与有料反馈；无密钥泄漏（前端网络请求里不含 key）；异常/超时有兜底；**断网/未登录时"AI 评估"按钮隐藏或提示不可用，选择/填空本地判分与阅读进度照常。**

---

## Phase 4 · 账户系统与排名（第 5 项）— 认证 + 数据库，最重

**这是最大的一跃：进度从 cookie 迁到服务端账户。**

- 认证：用 **SWA 内置认证**（GitHub/微软/邮箱等 provider），拿到用户身份；避免自造密码体系。
- 数据：`/api` + 数据库（Cosmos DB free tier 等）存 `progress`、`quizScores`、`badges`；提供 `GET/PUT /api/progress`、`GET /api/leaderboard`。
- 迁移：登录后把本地 cookie 进度**一次性合并**上云；**未登录/离线时全程走 cookie 本地模式**，cookie 仍是即时真源，登录只做备份与同步、不替代 cookie。
- 排名：排行榜按完成篇数/正确率/称号；**保护隐私**——默认用昵称、可关闭上榜、不展示真实身份；未成年人默认不公开个人信息。
- **验收**：登录后进度跨设备同步；排行榜可展示且隐私开关生效；**断网/未登录时阅读/判分/进度/字典完全正常**，仅同步与排行榜隐藏或提示不可用，页面不报错、不阻断。

## Phase 5 · 邀请语文老师协作校验（第 6 项）— 依附账户

- 技术侧：在账户体系加 **teacher 角色**；教师端可见"待校验/被反馈"列表（来自 Phase 2 反馈 + Phase 0 存疑项），可标注"通过/需改/读音订正"，订正回填到 `content/raw`/`samples` 的校对流程。
- 流程侧（非代码）：拟一份"教师协作说明"（校验范围、原文/读音/注释规范、提交方式），把 `docs/pinyin-校正报告.md` 的"存疑待核"作为首批任务。
- **验收**：教师账户能看到并处理校验任务；订正能走回源文件 + 重建流程；有一份可对外发的协作说明文档。

## 贯穿全程的纪律

- **每阶段**：`npm run build`（build:data + validate-data + validate-curriculum）全绿 → `git commit` → 再下一阶段；能上线的先上线。
- **单一真源**：内容仍以 `content/` + `data/curriculum.json` 为源，生成物不手改。
- **密钥安全**：任何 API 密钥/连接串只放后端 Function 环境变量，**绝不进前端代码或仓库**。
- **未成年人优先**：最小收集、家长同意、可删除、隐私默认从严；AI 反馈鼓励且仅限学习内容。
- **本地优先（见文首原则）**：cookie 是学习进度的唯一即时真源；在线功能一律可降级，未登录/离线时自动隐藏或提示，绝不阻断学习。每个后端 Phase 验收都要跑"断网 + 未登录仍能正常学"的检查。

## 给 Codex 的驱动方式

按 Phase 顺序执行，一次只做一个 Phase：先复述该 Phase 的目标与交付物、列出将新增/改动的文件与所需决策（如 AI 提供方、数据库选型）等我确认，再动手；完成后跑 `npm run build`、给出验收结果与 commit，等我确认再进入下一个 Phase。涉及后端的 Phase（2/3/4）先只搭最小可用骨架（本地可跑、密钥用占位），再逐步完善。
